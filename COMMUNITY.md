# Community

This repository separates conversation from implementation work so contributors can find the right place quickly.

## Ask and answer

Use GitHub Discussions for:

- how-to and usage questions,
- technical Q&A,
- learning conversations,
- design exploration,
- early ideas,
- examples and show-and-tell.

Discussions: https://github.com/AmirMotefaker/Create-your-own-ChatGPT/discussions

For a question with a concrete answer, use the **Q&A** category. The discussion author or a maintainer should mark an answer only when it actually resolves the question.

## Track work

Use GitHub Issues for:

- reproducible bugs,
- scoped feature requests,
- work that is ready to plan or implement.

Issues: https://github.com/AmirMotefaker/Create-your-own-ChatGPT/issues

## Contribute

See `CONTRIBUTING.md` before opening a pull request.

The standard `good first issue` and `help wanted` labels are reserved for genuine contributor-ready work. They are not used to manufacture activity.

Accurate human co-authorship is welcome when multiple people materially contribute to one change.

## Security

Follow `SECURITY.md`. Do not publish credentials, exploit details, private data, or sensitive vulnerability information in Issues or Discussions.

## Community health

- Be specific and constructive.
- Search before posting duplicates.
- Prefer reproducible examples.
- Keep implementation PRs focused.
- Do not create no-op work for stars, badges, contribution counts, or other metrics.
